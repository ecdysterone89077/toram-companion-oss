Date: 2026-10-19, Asia/Jakarta.

## Live acceptance result: FAILED

The operator's new PID19500 test displayed 1,358 critical damage and a death
animation while enemies remained alive/untargetable as reported. The screenshots
show a full Torpo HP bar alongside the damage number. The log confirms command 81
was enabled successfully in that process. Worker command success establishes

The +1000 feature is **not fixed**. The implementation below describes a local

No server cap, rejection code or validation formula has been recovered.

## Behavior

The new **+1000 CD [81]** menu option adds 1,000 percentage points to the current
native `get_CriticalDmg` result. Native 150 becomes 1150, corresponding to an
11.5x critical multiplier at the inspected native multiplication stage. Native
212 becomes 1212. Final damage still depends on other native calculation terms.

This is an additive calculator setting, distinct from adding 1,000 raw damage or
selecting an absolute 1,000% multiplier. Existing 175/200/250/300 presets select
absolute percentages. All critical-damage settings share one request value.

Use:

1. Restart the game normally after installing the new binaries.
2. Open canonical `companion.exe` (Game Companion v95.2).
3. Enable **Stability + Crit Settings** (F2 / 73).
4. Select **+1000 CD [81]**. The request display reads **Native +1000**.
5. Select **Native [79]** to restore the original critical-damage calculation.

The setting applies while the F2 hooks are enabled. Turning F2 off restores its
owned hooks; the selected request remains available for the next enable.

## Implementation

- `protocol::CommandId::CritDamageAdd1000` is command 81. Menu, loader and worker
  use the shared command-range check; command 80 remains the combat observer.
- Existing `crit_multiplier_pct` IPC field encodes additive mode as -1000; zero
  means Native and supported positive values remain absolute percentages.
  The binary layout stays unchanged and telemetry compatibility advances to 952.
- Both battle/secondary critical-damage callbacks obtain the original native
  result. At the outermost read, additive mode uses `saturating_add(1000)`.
- A thread-local RAII read guard makes nested hooked calculator reads return
  their native values, so a battle getter forwarding through a secondary getter
  does not receive the bonus twice. The guard restores its prior state on exit.
- Reset returns the current native getter value. Repeated selections do not
  mutate a stat, accumulate bonuses or reuse a previously boosted result.
- Critical-damage getters are essential hook entries: installation failure
  causes the F2 transaction to roll back instead of silently omitting the feature.
- GUI shows +1000 CD [81] alongside the existing presets and Native reset.
  The command entry accepts 0..81 and telemetry labels the additive request.

The existing critical-selection, stability, hit classification and native
damage forwarding paths remain in use. This feature adds no late damage-record
stamping, primary-stat mutation, MP refill, distance override or received-HP edit.
