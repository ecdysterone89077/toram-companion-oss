# Toram Companion v96 — combat and control upgrade

Version 0.96.0, telemetry layout 960. Built and checked on Windows x64 with
Rust 1.99.1 / MSVC. The six-crate workspace still has no external crate dependencies.

## Combat behavior

The old CommandRunner rejected every command above 80. This made damage buttons
81/83/84/85, feedback capture 82 and MP bonuses 86/87/88 unreachable through the
menu runner. Those commands now pass the shared protocol validation and reach
the selected target dispatcher.

Four repeatable profiles set explicit feature states:

| Profile | Critical request | MP request | Enabled features | Feedback |
| --- | --- | --- | --- | --- |
| Native | Native | Native | None | Off |
| Balanced | Native +100 | Native | Stability/crit, instant attack, anti-rigidity | On |
| Burst | Native +300 | Native | Stability/crit, instant attack, anti-rigidity | On |
| Recovery | Native +100 | Native +10 AMPR | Balanced features plus MP recovery | On |

Profiles turn other toggle features off and stop any passive native-only
observation session first. Clicking a profile twice leaves the same requested
state; it does not toggle the features back off.

Burst keeps the existing full basic-attack boost and adaptive skill cap of
+100..+200. Basic-attack responses no longer advance the skill acceptance
streak. These are requested calculations, not a guarantee of accepted damage.
Recovery still uses the existing experimental AMPR path. The dead-getter /
server MP investigation from v95.8 is not declared solved by this release.

## Feedback and telemetry

- Explicit feedback ON/OFF commands, independent of toggle 82.
- Counts of received accepted, rejected and unclassified attack responses.
- Current adaptive skill cap, last received mob HP and violation value.
- MP hit/getter invocation counts, with an explicit counter reset.
- Resource sample age from a monotonic Windows clock; settings/receipts do not
  refresh the resource timestamp.
- Unknown telemetry remains unknown, and unavailable clients show no invented
  zero-HP result. All-client toggle badges display MIXED or ? when appropriate.

Received response counts are observations, not attributed DPS, kill/reward proof,
or a recovered server formula. Existing native callbacks still receive their
original arguments and return through the original implementation.

## Controls and command execution

- Select one client or all clients in the GUI and CLI.
- GUI selection pins PID, creation time and full image path; refresh preserves
  a missing selection rather than silently switching it to all clients.
- Resolve every batch target before dispatch; every delivery retains the final
  process-handle identity validation from the security patch.
- Validate the complete batch before target resolution. Malformed entries,
  unsupported IDs, empty segments, blocked command 44 and overlong batches fail.
- One runner busy guard covers the entire batch, including gaps between commands.
- Stop on the first failed delivery, preserving per-client outcomes.
- Cancel between deliveries. An already running remote call finishes under the
  existing loader/worker timeout; cancellation never terminates its game thread.
- Save/load validated command plans. Loading in the GUI fills the input; Run
  batch executes it. No automatic application at startup.
- Hotkeys use MOD_NOREPEAT. Registration failures roll back, and the window
  ignores hotkey messages while the hotkey switch is off.
- The rebuilt panel fits the checked desktop at its display scaling.

## Usage

Run the project-root companion.exe, or the matched copy in work/release-v96/.
The core and loader are in src/ next to the menu. Restart the game normally
before loading a different core build; old and new core hooks are not stacked.

    companion.exe --clients
    companion.exe --profile balanced --pid 1234
    companion.exe --profile burst --all
    companion.exe --profile native --all
    companion.exe --cmd "83+111+109+115+89" --first
    companion.exe --save-plan burst.tcmp --profile burst
    companion.exe --load-plan burst.tcmp --pid 1234
    companion.exe --status-json --all > status.json

The GUI Save plan / Load plan buttons use commands.tcmp in the menu's release
folder. A working example is included. Profile files contain a version marker,
name and validated command list, without credentials or executable scripts.

Build:

    cargo test --workspace
    cargo build --release --workspace

Build outputs: target/x86_64-pc-windows-msvc/release/.
